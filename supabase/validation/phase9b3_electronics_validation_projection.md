# Phase 9B.3 backend proposal (not deployed)

- Live table summary reports 45 attribute definitions and 832 mappings, matching the V6 baseline. Public REST metadata reads returned HTTP 401, so per-code collisions and per-category mapping conflicts remain unverified. Recheck them with an authorized read-only preflight before any migration approval.
- Validate `CONDITION` only when provided: exact values `New`, `Open Box`, `Like New`, `Slightly Used`, `Used`, `Refurbished`, `For Parts`. Missing condition on existing products remains valid and unspecified. Validate `BATTERY_HEALTH_PERCENT` only when provided: finite numeric value from 0 through 100. Neither may be a variant option.
- Enforce these rules in the transaction-backed `adishop_seller_save_variant_catalog` path and its selected-store wrapper before deleting/replacing attribute values. Recheck persisted values in the seller submission RPC before changing review state. Return distinct safe validation errors. The existing Android checks are advisory only.
- `adishop-seller-update-product` currently saves base fields before calling the variant-catalog RPC. Add a pre-write payload check to the existing Edge handler so invalid new fields cannot leave base-field changes behind; retain the database checks for direct/RPC callers. Do not change the endpoint URL or authorization flow.
- `adishop_product_catalog_payload` currently projects all structured `shop_product_attribute_values` for the product. Filter private identifier codes and labels server-side before constructing the public JSON; retain source rows for seller/admin access. Separately reject or redact high-confidence IMEI/serial patterns embedded in seller free-text values, with a reviewed policy that avoids silently deleting legitimate descriptions. Audit any other public catalog path before enabling the new metadata.
- Stage tests: optional legacy condition, every canonical choice, invalid choices, 0/100 bounds and out-of-range values, variant-option rejection, failed-save atomicity, selected-store authorization, and public API privacy for typed and free-text identifiers. No production SQL or Edge deployment is authorized here.
